## 3. 演练流程

首页 → 免费检查 → 选择检查通过 → 生成演练结果 → 确认关联 → 确认订单 → 勾选服务说明 → 演练付款成功 → 演练继续安装。全程不扣款、不安装软件。

再演练 BLOCK 与 UNKNOWN：不能下单。通过结果有效 30 分钟；过期必须重查。相同演练码在有效期内沿用检查会话；重复提交待支付或已支付订单返回原订单。

我的订单 → 恢复关联 → 确认关联：沿用原订单。取消订单不发放权益；演练退款撤销后续领取资格；多次演练领取只增加尝试记录，不重复收费。

## 4. 真实接入边界

当前检查、关联、付款、退款及领取均为本地模拟；不生成可信设备证明，不接微信登录或正式后台。演练输入 DEMO-PASS 等只用于测试，不能复用为生产关联码。

真实模式拒绝模拟下单。下一阶段由服务端生成高强度随机、限时、单次关联凭证，实施微信账号认证与双端确认；关联结果和订单资格由服务端校验。

安装版本采用一期固定安装器 3861473；模拟检查规则 miniapp-demo-v1 不等于 preflight 正式规则。正式规则版本、WARN 映射和目标环境硬件门槛须结合安装器验收确定。

## 5. 待实现的后台接口契约

POST /api/mini-program/session：微信临时 code 换业务会话，不在客户端保存 AppSecret。GET /api/products/{id}：服务端价格与权益；客户端价格仅展示。

POST /api/link-sessions/{token}/claim 与电脑确认接口：双端关联。GET /api/check-sessions/{id}：最小检查摘要、规则、版本与过期时间；禁止读取其他账号记录。

POST /api/orders：检查有效资格、商品上架状态、权益和幂等键。GET /api/orders 与 GET /api/orders/{id}：账号内查单。

支付参数、可信通知或查单、幂等发放、退款和短期领取令牌须按新小程序实际开通能力实现；不根据客户端 success 发放。以上路径是待评审契约，不是现网接口。
